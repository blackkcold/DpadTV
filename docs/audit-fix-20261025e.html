5 · 潜在问题（本轮未消除的残留风险）

#风险等级说明 / 触发条件
R1年份覆盖只有 30.7%中508/1656。组合只补了 电影·国产剧·韩剧·日剧·美剧 × 2023–2025；「日本 ∩ 2025」「悬疑 ∩ 2025」仍只 1~3 条，会落网络（2.5s 节流，风控时 60min 退避）。UI 已在年份 chip 后标「· 联网」
R2年份标签 = 评分前 60，不是全量中本地年份筛选给的是「该年高分行」，不是「该年所有片」。文案上不能承诺「全部 2025」
R3直连抓取仍会触发风控中本轮实测韩剧组合首轮全失败。补量脚本建议改走 --via，或把 combo-pages 降到 2 并加长 gap
R4GridView 子项聚焦模型不一致中浏览/片单网格子项 isFocusable=true，详情选集靠列表持焦。两种模型并存，滚动到第一屏外是否可达需真机确认
R5详情页头部仍无硬性高度上限低片名 2 行 + 简介 3 行已收口，但 4 行元信息 + 按钮行在 540dp 屏上仍可能把 epGrid 压得很薄
R6ImageLoader 无 in-flight 合并、按条数计量中hero 960×540 单张约 2MB 堆；连续快速聚焦十几个标题有 OOM 面。缓存键含尺寸 → 同图两份
R7继续观看仍是单 URL中历史没有整季地址列表：自动连播、上下集、换源都做不到；错误提示只是改成不误导
R8lastFailure / lastSource 是共享可变字段低首页串行取数，但浏览页与首页可能并发；失败文案有概率张冠李戴（不影响数据）
R9片单主键是片名低「片名 · 第 N 集」「国语/粤语版」会分叉成多条；播放路径已不写库，但详情页「加入片单」仍按片名写
R10索引首次加载在主线程低52KB gzip → 1656 条解析，懒加载在第一次本地查询时发生；未测耗时，冷启动可能几十毫秒级抖动
R11versionCode 仍是 102低靠 adb -r 覆盖没事，但应用内更新通道按 versionName 1.2.0 比较，不会认为有新版本
R12UI 层零测试覆盖中37 个单测全是纯函数（IndexCore/Merger/Theme/DollarUrls/Recommend）；本轮改动大头在 View 构建与焦点
R13焦点顺序发生变化中详情页片名、浏览页状态行新增为可聚焦节点，D-pad 走位与之前不同，需真机确认没有「卡在标题上」
R14播放器错误文案依赖 urls.size低整季播放时 urls.size>1 会提示「换一集/换源」，但实际换源入口仍在详情页
