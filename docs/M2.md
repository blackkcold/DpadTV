# M2 记录：浏览页 chip + 四维筛选 + 存为榜单

## 做了什么

| 能力 | 实现 |
|---|---|
| chip 条 | 预设榜（热门/Top250/奥斯卡/9分+/2025/华语/悬疑）+ 我的榜单 + ＋存为榜单 |
| 四维筛选 | 年份 / 地区 / 类型 / 排序（评分·热门·最新 → 豆瓣 sort T/S/U） |
| 分页 | `start` 游标，滚到底自动加载下一页 |
| 存为榜单 | 弹窗预填「电影 · 2025 · 8.5分+」，确认即落 SharedPreferences（`dpadtv_chips`） |
| chip 走 ref 缓存 | Top250 点开直接命中首页已拉过的 50 条，0 网络请求 |
| 秒开 | 「查看更多」先把首页合并结果带进去，再按需刷新 |

## 豆瓣限流：这是本阶段最大的工程约束

实测返回体（HTTP 仍是 200）：

```json
{"msg":"检测到有异常请求从您的IP发出，请登录再试!","r":1}
```

一天内被触发 3 次，都是因为短时间并发请求。结论：

1. **请求必须串行**：所有抓取走一把 `Mutex`，全局同一时刻只有一个请求在飞。
2. **间隔 ≥ 2.5s**：650ms / 1.5s 都会在 4–6 个请求后触发；2.5s 后 12 个请求的冷启动未再触发。
3. **首页单条流水线**：一行拉完再拉下一行，不要 4 个 ref 并发。
4. **识别 + 退避**：命中即退避 10 分钟，期间只读缓存，UI 明确提示「豆瓣限流，N 分钟后自动恢复」。
5. **过期缓存兜底**：拉取失败时回退到过期缓存（`ttl = Long.MAX_VALUE`），宁可旧一点也不要空屏。
6. 缓存键：首页按 `ref.id`（可复用上次结果），浏览页按 `q_<md5(url)>`（筛选组合各自缓存 24h）。

## 已知取舍

- 模拟器里 **点一下 chip 只会聚焦、要再按 OK 才触发**（TV 遥控器本来就是焦点 + OK，不受影响）。
- 豆瓣没有「奥斯卡」这类标签，必须走豆列（`doulist/240962`，25 条/页）。
- 剧集标签（国产剧/美剧/韩剧/日剧）在 `new_search_subjects` 里时有时无，空了就靠「换筛选」提示。
